01 / The product

What MKodi does

MKodi brings taxpayer identity, business information, land records, compliance scores, and payment activity into one simple portal. It gives taxpayers a clear self-service experience and gives administrators a structured back-office record cabinet.

For taxpayers

Register with a TIN, view official details, check revenue intelligence, create payment requests, review payment history, manage a profile photo, and change a password.

For administrators

Maintain taxpayer records, manage payment records, search and filter data, delete records, export CSV reports, and review Django's built-in audit history.

Connected data

Admin-managed TIN, NIDA, contact, business, BRELA, land parcel, estimated income, compliance, and credit information becomes the source of truth for the user account.

Access channels

The project includes web portal, GePG payment requests, mobile-money demo handling, and a simulated USSD menu for low-connectivity access.

Core idea: one TIN connects the taxpayer account to the official admin-managed taxpayer record.

02 / Main workflows

A simple taxpayer journey

1. Admin preparesCreate the taxpayer record and enter official details.
2. Taxpayer registersEnter the matching TIN and choose a password.
3. Record linksMKodi loads the admin data into the account.
4. User actsView intelligence, pay, and manage security.

Dashboard

The dashboard shows compliance score, credit score, account status, reminders, and quick access to the 360-degree view and payments.

360-degree Revenue Intelligence

The intelligence page presents personal information, business and BRELA data, land/property details, estimated income, compliance score, credit score, risk level, and assessment.

Payments

A taxpayer chooses an amount and method: USSD, GePG, or mobile money. The request receives a control number and appears in payment history. Receipts show the taxpayer, amount, method, control number, transaction ID, status, and timestamps.

Profile

The profile page displays all linked taxpayer details, account-link status, profile photo, and password-change controls.

03 / Administration

The admin record cabinet

Administrators create the trusted taxpayer record before the taxpayer opens an account. This avoids duplicate data entry and keeps official values separate from login credentials.

Record areaStored detailsUsed by
IdentityTIN, NIDA, full name, phone, emailSignup, profile, 360 view
BusinessBusiness name, BRELA number360 view, reports
PropertyLand parcel and land records360 view
IntelligenceIncome, compliance, credit, riskDashboard, 360 view
PaymentsAmount, method, status, control and transaction IDsHistory, receipt, admin

Search and export

Search taxpayer records by TIN, NIDA, or name, filter active/compliance values, select records, and export CSV.

Audit trail

Django automatically records admin additions, edits, and deletions in its LogEntry history.

Roles to create

TRA Officer, Payment Officer, and Read-only Auditor groups can be created with only the permissions each role needs.

Analytics

The admin dashboard shows taxpayer count, active records, payment count, total amount, average compliance, and pending payments.

04 / Setup and next steps

Run the project

Install and start

cd mkodi
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver 3000

Open http://127.0.0.1:3000/ for the portal and /admin/ for administration.

Demo checklist

  1. Create a taxpayer record in admin.
  2. Register using the matching TIN.
  3. Review Dashboard, 360° View, Payments, and Profile.
  4. Create a payment request and open its receipt.
  5. Upload a profile photo and change the password.
  6. Use admin search, filters, delete, and CSV export.

Production readiness

Before deployment, use a strong secret key, set DEBUG=False, configure HTTPS and secure cookies, replace demo payment handlers with authenticated provider clients, migrate from SQLite to PostgreSQL, and schedule encrypted backups.

Current status: the project is a working demonstration. Government and payment integrations still require official credentials, API contracts, and provider approval.
